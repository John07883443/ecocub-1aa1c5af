# Библиотека реализованных решений EcoCub / Cubox

Контур данных для проверенных планировок. Runtime-подбор использует **только**
нормализованные и проверенные человеком записи: сырые PDF, DWG и презентации
сами по себе базой знаний не являются.

## Структура

```text
data/reference-projects/
  README.md                      — этот файл
  schema/project-manifest.schema.json — JSON Schema записи (версия 1)
  <project-id>/
    manifest.json                — нормализованная карточка проекта
    source/                      — исходники (PDF/DWG/фото), в runtime не читаются
    normalized/                  — этажи, меблировка, фасад в JSON
    previews/                    — изображения для внутреннего просмотра
```

## Правила заполнения

1. `status` — честный: `concept` (эскиз), `designed` (спроектирован),
   `produced` (произведён), `built` (построен). Не помечайте демонстрационный
   пример как построенный объект.
2. `verified: true` ставит человек, проверивший геометрию и семантику. Пока
   `verified: false`, запись не участвует в подборе и в пресетах.
3. Персональные данные запрещены: ФИО, телефоны, точные адреса. Для географии
   достаточно региона/климатической зоны, если она влияет на решение.
4. Размеры — в метрах, площади — в м². Габариты модуля и высота потолков —
   в стандарте проектирования: `src/lib/standards/ecocub.ts` и
   `docs/STANDARDS.md`.
5. Ссылки на изображения — относительные пути внутри папки проекта, без
   публичных URL.

## Как запись попадает в продукт

```text
source/ → нормализация → проверка архитектором (verified) → пресеты и retrieval
```

Разобранные по чертежам проекты живут в `src/lib/standards` — там они
нормализованы до констант и покрыты тестами. Эта папка остаётся местом для
сырых исходников и записей, которые ещё не разобраны.

До накопления достаточного количества сопоставимых проверенных примеров
библиотека используется как источник **пресетов и похожих решений**, а не как
основание для обучения модели. Наличие папки само по себе ничему модель не
«обучает».

## Что сейчас лежит

`demo-modular-01` — демонстрационная запись, собранная из уже существующей в
репозитории планировки шаблона конструктора. Статус `concept`,
`verified: false`: это пример формата, а не реализованный объект.

Недостающие производственные данные перечислены в
[`DATA_REQUIRED_FROM_ECOCUB.md`](../../DATA_REQUIRED_FROM_ECOCUB.md).
