

# План: перенос сайта Ecocub с Тильды на React + Tailwind

## Входные данные

- Архив `ecocub.zip` загружен (HTML-экспорт Тильды).
- Структура внутри: `ecocub/files/`, `ecocub/images/`, `ecocub/css/`, `ecocub/js/` + HTML-файлы страниц в корне.
- Сайт большой («больше 15 страниц»), нужен дизайн «близко по духу» + работающие формы.

В режиме плана я не могу распаковать архив — это будет первым шагом после твоего «ок».

## Подход: 2 фазы

### Фаза 1 — Распаковка и аудит (без верстки, ~быстро)

1. Распаковать `ecocub.zip` во временную папку.
2. Составить **полный список страниц** (все `.html` в корне) — сколько их реально, как называются.
3. Извлечь общие данные:
   - **Палитра цветов** (из inline-стилей и CSS)
   - **Шрифты** (какие подключаются, чем заменим — Google Fonts)
   - **Логотип и ключевые изображения** (из `images/`)
   - **Структуру меню** (из шапки на главной)
   - **Контент каждой страницы** (заголовки, тексты, картинки)
   - **Все формы** (поля, названия, куда шлют)
4. Скопировать нужные изображения в `src/assets/` (логотип, hero) и `public/` (большие галереи/каталоги).
5. **Показать тебе результат аудита**: список страниц, превью палитры/шрифтов, перечень форм. На этом шаге — твой ок: «делаем все страницы / только эти / объединить такие-то».

### Фаза 2 — Реализация

После твоего одобрения списка страниц:

1. **Базовый каркас**
   - Палитра в `src/styles.css` (oklch-переменные под цвета Ecocub)
   - Шрифты подключаем через Google Fonts в `__root.tsx`
   - Общие компоненты: `<Header/>`, `<Footer/>`, `<Container/>`, `<Section/>`
   - Шапка с навигацией и мобильным меню (Sheet из shadcn)
   - Подвал с контактами / соцсетями / копирайтом
2. **Страницы** — каждая отдельным роутом TanStack Router в `src/routes/`:
   - `index.tsx` → главная
   - `about.tsx`, `services.tsx`, `contacts.tsx`, и т.д. — по списку из Фазы 1
   - У каждой страницы свой `head()` с title/description/og:title (для SEO)
   - Если страниц однотипных много (каталог/кейсы/услуги-карточки) — **одна страница-шаблон + база данных** в Lovable Cloud, контент загружается из БД. Решим в Фазе 1 после просмотра.
3. **Формы → Lovable Cloud**
   - Включаем Lovable Cloud
   - Таблица `submissions` (тип формы, поля как JSON, дата, статус)
   - RLS: insert разрешён всем, select — только админу (через `user_roles` + `has_role`)
   - На сабмит: валидация (zod + react-hook-form), запись в БД, toast «спасибо»
   - На странице `/admin` (под паролем) — список заявок
4. **Адаптив и полировка**
   - Все секции — mobile-first (брейкпоинты sm/md/lg)
   - Анимации появления секций (Tailwind + `tw-animate-css`)
   - Замена картинок на оптимизированные форматы где возможно
5. **404 и ошибки** — уже есть в шаблоне, оставляем.

## Что улучшим относительно Тильды

- **Скорость**: чистый React-бандл вместо Тильдовского JS-конструктора (быстрее загрузка, лучше Lighthouse)
- **SEO**: каждая страница — отдельный URL с уникальными meta (TanStack Start даёт SSR из коробки)
- **Адаптив**: переверстаем на современных breakpoint'ах (на Тильде часто моб. версия = «втиснутая» десктопная)
- **Формы**: заявки реально сохраняются в БД, а не теряются в почте
- **Поддержка**: править контент в коде/БД, без подписки на Тильду

## Технические детали

- Стек: React 19 + TanStack Start + Tailwind v4 + shadcn/ui (уже настроено)
- Роутинг: file-based в `src/routes/` (отдельный файл на страницу, без хеш-якорей)
- Формы: `react-hook-form` + `zod` + shadcn `Form`
- Бэкенд: Lovable Cloud (Supabase) — таблицы `submissions` + `user_roles`
- Иконки: `lucide-react`
- Картинки: логотип/иконки → `src/assets/` (импорт ES6), фото каталога → `public/images/`
