# Что нужно, чтобы включить боевую генерацию

Код готов и выключен. Ниже — ровно то, чего не хватает, и переменные, которыми
это включается.

## Контракт запроса

Задание создаётся POST-запросом на путь модели. Путь **составной**, по образцу
`{поставщик}/{модель}` — как в документации `higgsfield-ai/soul/standard` и
`reve/text-to-image`. Для GPT Image 2 поставщик OpenAI:

```
POST https://platform.higgsfield.ai/openai/gpt_image_2
```

Значение задаётся переменной `AI_LAYOUT_SUBMIT_PATH=openai/gpt_image_2`.
Умолчания в коде намеренно нет: живая проверка 10.08.2026 показала, что
`POST /gpt_image_2` возвращает `model_not_found`, и подставлять путь наугад
дороже, чем честно сообщить «не настроена». Переменная позволяет исправить
адрес без правки кода и без выкладки, если каталог платформы изменится.

Путь один и для генерации с нуля, и для правки по референсу — маршрутизация
привязана к модели, а не к режиму. Режим задаётся телом: без массива `medias`
это text-to-image, с ним — генерация по исходнику.

Эндпоинта со списком моделей в публичном API нет. Актуальные составные
идентификаторы смотреть в каталоге кабинета `cloud.higgsfield.ai`.

```json
{
  "prompt": "…собирается на сервере…",
  "aspect_ratio": "1:1",
  "medias": [{ "role": "image", "value": "https://eco-cub.ru/api/ai-layout/footprint?key=…" }],
  "params": { "resolution": "1k", "quality": "low" }
}
```

В ответе приходят `request_id` и готовая ссылка `status_url` — её и опрашиваем,
а не склеиваем свою: так адрес переживёт смену маршрутизации на той стороне.
Заголовок авторизации у обоих запросов один: `Authorization: Key {key}:{secret}`.

Статусы: `pending`, `queued`, `in_progress` — ещё не готово; `completed` —
результат в массиве `images`; `failed` и `nsfw` — отказ.

Что здесь подтверждено документацией: база, заголовок, опрос состояния и
статусы. Что назвал ассистент платформы: путь запроса, `medias`, `params`,
`status_url`. Первый живой запрос — проверка, а не формальность.

Расхождение, которое стоит помнить: в первом ответе ассистента модель
предлагалось дублировать полем `job_type` в теле, но в присланном примере cURL
его нет. Выбран пример. Если платформа ответит ошибкой вида «не указана
модель» — вернуть поле в тело запроса, это одна строка в `provider.ts`.

Тариф `1k` + `low` выбран по замерам этапа 0: 0.5 кредита за генерацию при
точном контуре и полной планировке.

## Переменные окружения

| Переменная                   | Назначение                                     | По умолчанию         |
| ---------------------------- | ---------------------------------------------- | -------------------- |
| `AI_LAYOUT_ENABLED`          | главный выключатель функции                    | выключено            |
| `AI_LAYOUT_KILL_SWITCH`      | аварийный стоп, сильнее предыдущего            | выключено            |
| `AI_LAYOUT_PROVIDER`         | `mock`, `manual` или `higgsfield`              | `mock`               |
| `AI_LAYOUT_VISITOR_SECRET`   | соль для HMAC поверх IP, обязательна           | нет                  |
| `AI_LAYOUT_SUBMIT_PATH`      | адрес создания задания, обязателен для боя     | нет                  |
| `HIGGSFIELD_API_KEY`         | ключ платформы                                 | нет                  |
| `HIGGSFIELD_API_SECRET`      | секрет платформы                               | нет                  |
| `AI_LAYOUT_JOB_TYPE`         | идентификатор модели                           | `gpt_image_2`        |
| `AI_LAYOUT_RESOLUTION`       | разрешение                                     | `1k`                 |
| `AI_LAYOUT_QUALITY`          | тариф качества                                 | `low`                |
| `AI_LAYOUT_FREE_PER_VISITOR` | бесплатных генераций на посетителя             | `1`                  |
| `AI_LAYOUT_DAILY_LIMIT`      | потолок генераций в сутки                      | `50`                 |
| `AI_LAYOUT_PUBLIC_BASE`      | адрес сайта: по нему провайдер забирает контур | `https://eco-cub.ru` |

Секреты живут только в окружении сервера. В браузер уходит четыре поля —
доступна ли функция, заглушка ли это, ручной ли режим и сколько бесплатных
генераций положено; проверено тестом.

## Куда класть ключи

Ключи выпускаются в консоли `cloud.higgsfield.ai` (раздел API Keys). Секрет
показывается один раз — если потерян, ключ перевыпускается.

В репозиторий они не попадают никогда: мост между локальным и облачным агентом
— это git, а всё, что попало в git, остаётся в истории навсегда.

Переменные окружения боевого сервера лежат в `/home/deploy/ecocub.env` с
правами 600. Сам `ecosystem.config.cjs` их не хранит, а читает оттуда
функцией `readEnvFile` — поэтому секреты не оказываются в файле конфигурации,
который можно случайно скопировать или показать, и ошибка в них не валит
процесс целиком. Там уже лежат токены Telegram и прочее.

Добавляются строками в `ecocub.env`:

```
HIGGSFIELD_API_KEY=…
HIGGSFIELD_API_SECRET=…
AI_LAYOUT_VISITOR_SECRET=…
AI_LAYOUT_PROVIDER=higgsfield
AI_LAYOUT_ENABLED=0
```

Затем `pm2 reload ecocub --update-env`.

`AI_LAYOUT_VISITOR_SECRET` — не ключ платформы, а наша соль для счётчика
бесплатных генераций (`openssl rand -hex 32`). Придумывается один раз и не
меняется: от неё зависит опознание посетителей, смена обнулит счётчик всем.

## Порядок включения

1. Выпустить ключи, положить их в env на VPS, оставив `AI_LAYOUT_ENABLED=0`.
2. Включить флаг, собрать дом и запросить одну генерацию.
3. Сверить контур результата с исходником и посмотреть списание в кабинете:
   должно быть 0.5 кредита.
4. Только после этого поднимать дневной лимит.

Если что-то пойдёт не так — `AI_LAYOUT_KILL_SWITCH=1` гасит функцию мгновенно,
не трогая остальные настройки.

## Что показала живая проверка 10.08.2026

Три запроса с боевым ключом дали разные ответы — и вместе они читаются
однозначно:

| Путь                          | Ответ                    |
| ----------------------------- | ------------------------ |
| `higgsfield-ai/soul/standard` | `403 not_enough_credits` |
| `openai/gpt_image_2`          | `404 model_not_found`    |
| `gpt_image_2`                 | `404 model_not_found`    |

**Ключи рабочие.** Ни одного 401: платформа принимает заголовок
`Authorization: Key key:secret`, ключи доезжают до процесса.

**Форма пути правильная.** Модель из документации разрешается и доходит до
проверки баланса. Значит синтаксис адреса был ни при чём.

**GPT Image 2 этому аккаунту через REST недоступна.** 404 на фоне 403 у другой
модели — это не опечатка в пути, а отсутствие модели в публичном API.

**У API отдельный кошелёк.** `not_enough_credits` пришёл при 189 кредитах на
балансе веб-продукта. То есть баланс `higgsfield.ai` (где работают MCP и
веб-интерфейс) и баланс консоли разработчика `cloud.higgsfield.ai` — разные
счета. Документация об этом молчит; выяснено опытом.

### Из этого следует

Барьера два, и они независимы:

1. **Пополнить счёт API** в консоли разработчика — не тот, что пополняли для
   веб-продукта.
2. **Выбрать модель, доступную в REST.** Замеры этапа 0 делались через MCP, то
   есть на каталоге веб-продукта; в REST этого каталога может не быть целиком.
   Тариф `1k` + `low` = 0.5 кредита тоже относился к GPT Image 2 и к другой
   модели не применим.

Требование к замене жёсткое: модель обязана принимать исходное изображение
массивом `medias` и удерживать контур. Из проверенных этому отвечают Kling O1
и Seedream 5.0 Pro в режиме inpaint — но их доступность в REST так же нужно
проверить, а не предполагать.
