# Бриф: блог как журнал — дизайн-система для лонгридов

## Контекст и цель

Сейчас статьи блога — это просто текст с обложкой, оформленный дефолтным
`@tailwindcss/typography` (`prose`). Владелец хочет, чтобы статьи читались
как в профессиональном журнале: сильная типографика, авторский ритм,
визуальное разнообразие — не только ради SEO-задержки на странице, а
чтобы реально хотелось читать. Он явно называет это будущим брендом
редакции: **«Эко Куб — Жизнь в Кубе»**.

Задача не «оформить одну статью красиво», а собрать **переиспользуемую
дизайн-систему блока** — набор блоков, из которых собирается любая
статья, в едином узнаваемом стиле. Ниже — разбор референсов, что уже
есть в проекте для опоры, предлагаемый набор блоков и техническая
механика их встраивания в контент.

Это осознанный MVP/прототип — владелец сказал «будем уточнять» тем же
тоном, что и на барометре цен: не строить финальную систему сразу,
собрать первую версию на одной статье и итерировать по обратной связи.

## Референсы (от владельца, Pinterest, 17.08.2026)

Владелец прислал 10 скриншотов. Общий язык через все:

- **Крупная жирная типографика**, часто смешанный/нестандартный регистр
  в заголовках (не Title Case, не капс сплошняком).
- **Нумерованные секции** (`01/`, `02/`, `03/`) как навигационный приём.
- **Минимум цвета** — чёрно-белое/монохром + один тёплый акцент.
- **Разноразмерная фотосетка** — не единая галерея, а осмысленный
  чейндж ритма: одно большое фото, потом два маленьких рядом, потом
  снова одно большое.
- **Крупные цитаты-врезки** в кавычках, отдельным акцентным блоком.
- **Авторский тон подписей** к фото (не «Изображение 1», а как в
  журнале — контекст, кто/что на фото).

Ближе всего по духу к нашей теме:
- **Kinfolk** (архитектура/интерьеры) — тёплая натуральная фотография,
  жирный кондовый заголовок, простые подписи под фото с деталями.
- **BIGHUT COMPANY** — прямой конкурент (модульные дома), нумерованные
  секции (01 О нас / 02 Проекты / …), чёрно-белая палитра с деревом,
  чистая сетка. Ближе всего технически к тому, что нам нужно.

## Что уже есть в проекте — строим на этом, не с нуля

`src/styles.css`:
- Шрифты: `--font-display: "Unbounded"` (жирный геометричный дисплейный
  шрифт — уже даёт нужный «журнальный» вес заголовкам) + `--font-sans:
  "Manrope"` для текста.
- Палитра: белый фон, почти чёрный текст (`oklch(0.18 0 0)`), тёплый
  бежевый акцент `#bc9b82` (`--accent`). Ровно тот монохром + один тёплый
  акцент, что и в референсах — ничего изобретать не надо, только
  применить последовательно к блокам лонгрида.
- `@plugin "@tailwindcss/typography"` уже подключён (починили 16.08) —
  `prose prose-neutral` в `blog.$slug.tsx` работает.

`content/blog/rastuschiy-dom-strategiya-dlya-2026-goda.md` (кандидат для
прототипа, как и предложил владелец) уже частично готов под этот стиль:
4 цитаты (`> ...`) — готовые кандидаты на блок «крупная цитата-врезка»,
2 списка через сырой HTML (`<ul><li data-list="bullet">`) — готовые
кандидаты на блок «список принципов», короткий панчовый ритм абзацев
(предыдущая правка от 16.08 уже разбила текст под long-read, не с нуля).

## ВАЖНАЯ ТЕХНИЧЕСКАЯ ЛОВУШКА — прочитать до реализации

`src/styles.css` подключает Tailwind так: `@source "../src"` — сканируется
**только `src/`**. Файлы в `content/blog/*.md` НЕ сканируются на классы
Tailwind. Значит писать `<div class="grid grid-cols-2 gap-4">`
непосредственно в теле markdown-статьи **не будет работать** — класс
уйдёт в prod-сборку без соответствующего CSS (PurgeCSS отбросит его как
неиспользуемый, раз он не встречается в `src/`).

Разметка контента идёт через `ReactMarkdown` + `remarkGfm` + `rehypeRaw`
(см. `blog.$slug.tsx`) — сырой HTML в теле `.md` уже проходит как есть
(поэтому текущие `<ul><li data-list="bullet">` работают), но именно
**Tailwind-утилиты в контенте — ловушка**, семантические теги и
`data-*`-атрибуты — нет.

Два рабочих пути (выбрать один, не мешать):
1. **Семантические теги + `data-block`-атрибуты в markdown**, стилизуемые
   выделенным CSS-блоком в `styles.css` (обычный CSS, не Tailwind-утилиты,
   так же как уже стилизован `prose`). Пример: `<blockquote
   data-block="pull-quote">…</blockquote>`, `<div
   data-block="image-grid-2">…</div>`. Плюс: минимальные правки
   `blog.$slug.tsx`, авторам статей писать разметку прямо в `.md`. Минус:
   немного HTML в контентных файлах.
2. **Кастомный remark-плагин**, который превращает простой синтаксис
   (например `::grid` / `::quote`) в нужную HTML-структуру на этапе
   парсинга. Плюс: контент остаётся чище. Минус: больше кода, отдельный
   плагин для remark-конвейера.

Рекомендация (не жёстко): начать с варианта 1 для MVP — быстрее
прототипировать на одной статье, не городя инфраструктуру заранее.
Если система приживётся и статей станет много — можно мигрировать на
вариант 2.

## Предлагаемый набор блоков (v1)

1. **Hero-заголовок статьи** — крупный `Unbounded`, возможно с более
   выраженным трекингом/интерлиньяжем, чем сейчас; обложка на всю
   ширину под ним или как фон с затемнением (решить по месту на
   прототипе — оба варианта есть в референсах).
2. **Цитата-врезка** (`data-block="pull-quote"`) — крупный акцентный
   блок, `«…»`, возможно с левым бордером в акцентном бежевом цвете.
   4 готовых кандидата уже есть в статье-прототипе.
3. **Список принципов** (`data-block="feature-list"`) — не буллеты
   маркером, а нумерованные пункты в духе `01/ 02/ 03/` из референсов,
   с жирным заголовком пункта и обычным текстом описания. 2 готовых
   кандидата уже есть в статье-прототипе (сейчас это простой `<ul>`).
4. **Разделитель секции** — визуальный акцент между `##`-секциями
   (тонкая линия/номер/воздух), чтобы не всё было сплошным текстом.
5. **Подпись автора/контекста** (опционально для v1) — блок в конце
   статьи в духе журнальной редакции («Эко Куб — Жизнь в Кубе»).

Сетка фото (2-3 колонки, разноразмерная) — сознательно НЕ в v1: в статье-
прототипе сейчас одна обложка, дополнительных фото под сетку нет. Это
следующая итерация, когда будем прогонять статьи с несколькими фото.

## Что НЕ входит в этот этап (MVP)

- Не трогаем список статей (`/blog`) и карточки (`BlogCard.tsx`) — только
  страница отдельной статьи.
- Не строим редактор/конструктор разметки для будущих статей — сначала
  проверяем на одной, вручную.
- Не делаем фотосетку (нет материала на статье-прототипе).
- Не меняем цветовую палитру и шрифты сайта — только применяем то, что
  есть, к новым блокам.
