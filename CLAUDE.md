# EcoCub — контекст проекта

## Две среды: облачный агент и локальный агент

У этого проекта работа ведётся из **двух** агентов Claude Code одновременно:

1. **Облачный агент** (Claude Code on the web / claude_code_remote).
   - Запускается в изолированном облачном контейнере (отдельная виртуалка).
   - Видит **только этот git-репозиторий**. Доступа к машине пользователя нет:
     ни к диску `D:`, ни к рабочему столу, ни к папке `ECOCUB`, ни к
     локальным архивам. Это ограничение среды, а не прав — внутри контейнера
     агент root.
   - Задача облачного агента: код сайта (React/TanStack Start), сборка,
     коммиты и пуш в ветку.

2. **Локальный агент** (Claude Code на Windows-ПК пользователя,
   каталог `C:\Users\superagent\ECOCUB`).
   - Имеет полный доступ к файловой системе ПК: локальные файлы, PowerShell,
     тильдовский экспорт сайта в виде zip (`ecocub_dcfac...zip`, ~70 МБ) и т.п.
   - Через него достаются любые исходники/ассеты, которых нет в репозитории
     (например фавикон и картинки из выгрузки Тильды).

## Как агенты обмениваются файлами

Прямого канала между агентами нет (`ListAgents` → «No reachable agents»).
**Единственный мост — этот git-репозиторий:**

- Локальный агент кладёт нужные файлы в репозиторий и пушит в ветку.
- Облачный агент делает `git pull` и продолжает работу над кодом.
- Для передачи разового файла пользователь может также прикрепить его прямо
  в чат облачной сессии (файл попадает в контейнер, в `/mnt/attach`).

## Всегда давать прямую ссылку на изменённый экран

После любой правки, ушедшей на боевой сайт, в ответе пользователю **сразу
давать прямую ссылку на страницу и на конкретный экран** (через якорь), чтобы
он мог быстро проверить результат. Пример: `https://eco-cub.ru/#technology`.

Якоря секций главной (`src/routes/index.tsx`, id на `<Section>`):
`#comparison` (сравнение технологий), `#about` (о компании/таймлайн),
`#modules` (принцип LEGO), `#quiz` (квиз подбора проекта),
`#dream` (сборка дома мечты из кубиков — карта потребностей),
`#builder` (тизер 3D-конструктора), `#technology` (05 · Технология),
`#calculator` (калькулятор цены), `#included` (что входит),
`#projects` (проекты), `#interiors` (интерьеры), `#stages` (этапы),
`#blog` (блок блога), `#contact` (форма связи).

Базовый компонент `Section` (`src/components/Container.tsx`) несёт
`scroll-mt-28 md:scroll-mt-32`, чтобы прыжок по якорю не залезал под липкую
шапку. Отдельные страницы: `/technology`, `/concrete`, `/portfolio`,
`/presentation`, `/contacts`, `/blog`, `/constructor` (3D-конструктор дома).
Если правишь экран без якоря — сначала добавь `id` соответствующей секции,
потом давай ссылку.

3D-конструктор дома: страница `/constructor`, код в `src/components/constructor/*`
и `src/lib/constructor/*`. Дом собирается из модулей-кубиков 3×3 м (высота 3,15 м);
шаг установки и перетаскивания модулей — 0,5 м, модули магнитно стыкуются
гранью в грань без зазора; в «Плане» модули
можно таскать мышкой/пальцем с точками-подсказками допустимых позиций; вкладки
«План» (2D SVG, для мобильных) и «3D»
(Three.js/@react-three/fiber — грузится лениво отдельным чанком, только на
клиенте). Площадь/стоимость/комнаты считаются в `geometry.ts`, стоимость — по
`site.basePricePerM2`. AI-генерация фасада пока не подключена (задел на будущее),
сейчас — мгновенные пресеты материалов в `constants.ts`.

Экспериментальный AI-конструктор V3: страница `/constructor-ai-v3` (noindex,
нет в меню и в sitemap), код в `src/components/v3/*` и `src/lib/v3/*`.
Единый путь: квиз → адаптивные вопросы об образе жизни → подбор до трёх домов
из библиотеки реальных планов (`src/lib/v3/plans.ts`: 5 карточек каталога с
`needsReview` + 6 шаблонов конструктора) → редактирование крупными действиями
с undo/redo (валидатор — боевой `geometry.ts`) → посадка на участок в масштабе →
фасад и manual-задание на AI-рендер → лид в `/api/lead`. Проект сохраняется в
localStorage (`ec_v3_project`). Скрытая витрина всех версий — `/constructor-lab`
(реестр: `src/lib/v3/versions.ts`). Юнит-тесты доменной логики: `npm run test:v3`
(node --test, без новых зависимостей). Недостающие данные производства —
`DATA_REQUIRED_FROM_ECOCUB.md`. Старые квиз/«Дом мечты»/`/constructor` не тронуты.

Итерация V3.1: страница `/constructor-ai-v3-1` (noindex, есть в меню
«Конструктор» и в `/constructor-lab`), код в `src/components/v31/*` и
`src/lib/v31/*`. Отличия от v3: модули магнитно стыкуются гранью в грань
(`geometry.ts`: snapCandidates/pickSnap с порогом в пикселях и гистерезисом),
дом обязан быть связным, внешний контур и стены вычисляются из объединения
секций; план монохромный без букв и цветовой кодировки, мебель расставляется
детерминированным планировщиком (`furniture.ts`, каталог габаритов и версия
алгоритма в `constants.ts`); появились типы помещений «прихожая», «кабинет»,
«столовая», «хранение»; площадь разделена на общую и жилую; высота потолков —
одна константа `CEILING_HEIGHT_M = 3.15` для UI и 3D; 2D и белый 3D
(`Scene31.tsx`) читают одно состояние, режимы «Вместе/План/3D»; дом и участок
редактируются на одном экране (переключатель «Дом/Участок», отдельного шага
посадки нет). Состояние — `useWorkspace.ts` (атомарные транзакции, undo/redo,
очистка), проект в localStorage `ec_v31_project`. Каталог фасадов и контракты
`RenderBrief`/`ImageRenderProvider` — `facade.ts`, генерация намеренно
отключена до появления серверного сервиса. Библиотека проверенных проектов —
`data/reference-projects/` (схема, README, честный demo-пример). Тесты:
`npm run test:v31`.

Практическое правило: если облачному агенту нужен ассет с ПК пользователя
(фавикон, изображения из Тильды, локальный env и пр.) — это добывает
локальный агент и пушит через репозиторий; облачный агент не пытается лезть
на машину пользователя.
