# EcoCub — контекст проекта

## Две среды: облачный агент и локальный агент

У этого проекта работа ведётся из **двух** агентов Claude Code одновременно:

1. **Облачный агент** (Claude Code on the web / claude_code_remote).
   - Запускается в изолированном облачном контейнере (отдельная виртуалка).
   - Видит **только этот git-репозиторий**. Доступа к машине пользователя нет:
     ни к диску `D:`, ни к рабочему столу, ни к папке `ECOCUB`, ни к
     локальным архивам. Это ограничение среды, а не прав — внутри контейнера
     агент root.
   - Задача облачного агента: код сайта (React/TanStack Start), сборка,
     коммиты и пуш в ветку.

2. **Локальный агент** (Claude Code на Windows-ПК пользователя,
   каталог `C:\Users\superagent\ECOCUB`).
   - Имеет полный доступ к файловой системе ПК: локальные файлы, PowerShell,
     тильдовский экспорт сайта в виде zip (`ecocub_dcfac...zip`, ~70 МБ) и т.п.
   - Через него достаются любые исходники/ассеты, которых нет в репозитории
     (например фавикон и картинки из выгрузки Тильды).

## Как агенты обмениваются файлами

Прямого канала между агентами нет (`ListAgents` → «No reachable agents»).
**Единственный мост — этот git-репозиторий:**

- Локальный агент кладёт нужные файлы в репозиторий и пушит в ветку.
- Облачный агент делает `git pull` и продолжает работу над кодом.
- Для передачи разового файла пользователь может также прикрепить его прямо
  в чат облачной сессии (файл попадает в контейнер, в `/mnt/attach`).

Практическое правило: если облачному агенту нужен ассет с ПК пользователя
(фавикон, изображения из Тильды, локальный env и пр.) — это добывает
локальный агент и пушит через репозиторий; облачный агент не пытается лезть
на машину пользователя.
